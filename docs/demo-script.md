# Сценарий демонстрации курсового проекта на защите (5-10 минут)

**Тема:** «Клиент-серверная система резервного копирования файлов с автоматической синхронизацией и ведением журнала изменений»

---

## Подготовка к демонстрации (до начала показа)

1. Убедитесь, что база данных PostgreSQL запущена:
   - Либо Docker: `docker compose up -d`
   - Либо локальная служба: `127.0.0.1:5432`
2. Примените миграции при первом запуске:
   ```powershell
   dotnet ef database update --project src/Backup.MetadataService --startup-project src/Backup.MetadataService
   ```
3. Подготовьте 4 отдельных окна PowerShell.
4. Создайте чистую демонстрационную директорию вне репозитория, например:
   ```powershell
   New-Item -ItemType Directory -Path "C:\demo_backup" -Force
   ```

---

## Шаг 1. Архитектурное введение (1 минута)

Покажите преподавателю общую схему архитектуры (`docs/architecture.md`):
- Объясните разделение на микросервисы:
  - **Blazor Client UI** (`localhost:5100`) — интерфейс оператора;
  - **SyncGateway** (`127.0.0.1:5000`) — пограничный оркестратор;
  - **MetadataService** (`127.0.0.1:5001`) — база данных PostgreSQL (версии, журнал аудита, права);
  - **StorageService** (`127.0.0.1:5002`) — физическое дисковое хранилище неизменяемых блобов.
- Подчеркните: все сервисы общаются по **собственному бинарному TCP Protocol v1** с кадрированием `BKP1` и потоковой передачей данных без полной буферизации в оперативной памяти.

---

## Шаг 2. Запуск сервисов (1 минута)

### Вариант 1 (Рекомендуемый — Запуск одной командой):
Выполните в PowerShell из корня проекта:
```powershell
.\start.ps1
```
Скрипт проверит доступность PostgreSQL, скомпилирует сервисы, запустит 4 независимых процесса и откроет браузер на `http://localhost:5100`.

*(Остановка по завершении показа: `.\stop.ps1`)*

### Вариант 2 (Классический запуск в 4 отдельных терминалах):
Если преподаватель просит показать вывод каждого процесса отдельно:
- **Терминал 1:** `dotnet run --project src/Backup.MetadataService` (порт 5001)
- **Терминал 2:** `dotnet run --project src/Backup.StorageService` (порт 5002)
- **Терминал 3:** `dotnet run --project src/Backup.SyncGateway` (порт 5000)
- **Терминал 4:** `dotnet run --project src/Backup.Client.Web` (порт 5100)

---

## Шаг 3. Регистрация и настройка набора (1 минута)

1. Откройте в браузере: `http://localhost:5100`.
2. Интерфейс полностью русскоязычный. Обратите внимание преподавателя на карточки состояния:
   - **Шлюз синхронизации:** `Подключено` (зеленый бэдж);
   - **Автоматическая синхронизация:** `Остановлено`;
   - **Согласование данных:** `Синхронизировано`.
3. Покажите блок **«Быстрый старт»** с наглядными шагами настройки.
4. Нажмите кнопку **«Проверить соединение»** (проверка TCP Ping/Pong — задержка < 5 мс).
5. Нажмите кнопку **«📝 Зарегистрировать клиент»**:
   - Клиент регистрируется через шлюз в PostgreSQL;
   - Отображается сгенерированный `ClientId` (UUID) и локальный файл `data/client/client-state.json`.
   - Подчеркните: ошибка рассинхронизации кадрирования полностью устранена.
6. В секции набора укажите:
   - Имя набора: `DemoSet`
   - Папка для резервного копирования: `C:\demo_backup`
7. Нажмите **«📁 Сохранить и активировать»**.

---

## Шаг 4. Автоматическая синхронизация и версионирование (2-3 минуты)

1. Нажмите **«▶️ Запустить синхронизацию»**.
   - Статус переключится в `Работает` (зеленый).
   - Запущен `FileSystemWatcher` с защитой от дребезга (debounce 750 мс).
2. Создайте файл в `C:\demo_backup\report.txt` с содержимым `Версия 1`:
   ```powershell
   Set-Content -Path "C:\demo_backup\report.txt" -Value "Версия 1 - Черновик отчета"
   ```
3. В логах отобразится:
   - Событие перехвачено, вычислен SHA-256, файл передан потоком в StorageService и зафиксирован в PostgreSQL как ревизия 1.
4. Отредактируйте файл:
   ```powershell
   Set-Content -Path "C:\demo_backup\report.txt" -Value "Версия 2 - Дополненные данные"
   ```
5. В интерфейсе перейдите на страницу **«Файлы и версии»** (`/files`):
   - Файл `report.txt` отображается с актуальной версией 2.
6. Нажмите на имя файла, чтобы открыть карточку версий (`/files/{id}`):
   - Виден список версий: Версия 1 и Версия 2 с точным временем, размером и хэшем SHA-256.

---

## Шаг 5. Переименование и удаление (1 минута)

1. Переименуйте файл:
   ```powershell
   Rename-Item -Path "C:\demo_backup\report.txt" -NewName "final_report.txt"
   ```
2. Обновите страницу `/files`:
   - Имя файла изменилось на `final_report.txt`, история версий сохранилась.
3. Удалите файл:
   ```powershell
   Remove-Item -Path "C:\demo_backup\final_report.txt"
   ```
4. На странице `/files` включите чекбокс «Показывать удаленные»:
   - Файл отображается со статусом `Удалён`.

---

## Шаг 6. Восстановление исторической версии (Restore) (2 минуты)

1. Откройте карточку удаленного файла `final_report.txt`.
2. Выберите историческую **Версию 1** и нажмите **«Восстановить версию 1»**.
3. Подтвердите операцию в модальном диалоге подтверждения (с предупреждением о защите правок).
4. Что происходит на сервере и клиенте:
   - Файл скачивается потоком из StorageService;
   - Записывается во временный файл `.restore.*.tmp` с проверкой SHA-256;
   - Атомарно перемещается в `C:\demo_backup\final_report.txt`;
   - Реактивируется в базе данных как **Версия 3 (RESTORE)**;
   - `RestoreSuppressionService` подавляет эхо-событие от FileSystemWatcher, исключая дубликат версии 4!
5. Проверьте содержимое на диске:
   ```powershell
   Get-Content "C:\demo_backup\final_report.txt"
   ```
   *(Отобразится исходный текст: `Версия 1 - Черновик отчета`)*.

---

## Шаг 7. Журнал изменений и целостность базы данных (1 минута)

1. Перейдите на страницу **«📜 Журнал изменений»** (`/history`):
   - Покажите журнал аудита: записи `Создание`, `Изменение`, `Переименование`, `Удаление`, `Восстановление`.
   - Продемонстрируйте выпадающий фильтр по действию (выберите `Восстановление` или `Удаление`).
2. Объясните концепцию физического хранилища:
   - В каталоге `data/storage/clients/...` лежат неизменяемые `.bin` блобы.
   - База данных содержит ссылки и хэши, а не бинарные файлы.
3. Завершите демонстрацию, остановив автоматическую синхронизацию кнопкой **«⏹️ Остановить синхронизацию»**.
4. Для остановки сервисов выполните: `.\stop.ps1`.

---

## Очистка после демонстрации

```powershell
Remove-Item -Path "C:\demo_backup" -Recurse -Force
```
*(Демонстрационный каталог удален, проект готов к следующему показу).*
